Implementation:
- Root cause of the desktop freeze was the yeast Environmental Conditions submenu being fully constructed before the main simulator menu appeared: 164 exchanges generated one label plus two toggle switches per exchange (plus margins), i.e. roughly 500 heavy pygame-menu widgets / ~660 menu elements at every opening.
- Added a model-level `environment_ui_mode`. E. coli keeps its familiar 20-exchange toggle interface unchanged; iMM904 now uses a compact four-field editor that records only explicit deviations from the model-default medium (lower open/close and upper open/close).
- The compact editor still generates the exact same complete `reaction_<index>_lb/ub` JSON-safe payload consumed by the existing solver and `/simulate` request path. No second scientific or web contract was introduced.
- Unknown exchange ids and contradictory open+close requests are rejected explicitly; they are never silently ignored. Empty fields reproduce the exact iMM904 default medium.
- Yeast Window construction is now lazy: iMM904 metadata/UI context is not created at game startup and is loaded only after Mission 35 when the Golden Lab computer is actually opened.
- This design is substantially safer for the future browser/WASM build because the main thread no longer has to allocate/render hundreds of bound widgets before yielding control to the UI loop.
